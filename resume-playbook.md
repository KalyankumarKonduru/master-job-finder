# Resume Bullet Bank

Ready-to-fill, one-line bullets for every tool pairing and concept in `resume-playbook.md`, organized by resume version.

---

## How to Use This

1. **Only use a bullet if it describes work you actually did.** Delete the rest. Every bullet must pass the two-minute interview test.
2. **Replace every [bracket]** with your real details. If you can't fill a bracket honestly, rewrite the bullet around a number you *do* have (scale, users, count), or drop it.
3. **Keep it to one line** after filling in. If it runs long, cut the least important detail.
4. **Match the job description:** pick bullets whose keywords match the posting, and swap in the posting's exact wording where true.
5. **Mix it up:** 1–2 two-tool bullets per job, the rest one tool or none.

### Placeholder guide

| Placeholder | Fill with |
|---|---|
| [X], [Y] | A real number: %, count, ms, seconds, hours, users, requests |
| [feature] | Specific feature name: login, checkout, request form, dashboard |
| [service] | Specific service or API name: order service, notification API |
| [product] / [app] | The product or app name, or a short description |
| [process] / [task] | The workflow you improved |
| [team] | Who used it: support team, 3 product teams, 50K employees |

### Types of numbers you can use

Time saved · latency (ms) · load time (s) · requests per day/second · users · records/events · % test coverage · uptime % · cost saved · releases per week · bugs or incidents reduced · screens/APIs/services built · team size · weeks to launch
